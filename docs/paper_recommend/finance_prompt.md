# 論文レコメンド プロンプト定義

  1. 基準期間の直前1週間

祝日等で対象日のリストが存在しない場合は、その旨を明記する。

━━━━━━━━━━━━━━━━━━━━━━━

フローはキーワード検索による非網羅的な探索である。

・日付は検索結果に対する後段フィルタとして適用する

対象:

  q-fin.RM / q-fin.MF / econ.EM
・arXiv: cs.LG / stat.ML のうち金融・経済応用のもの
・SSRN・NBER の新着WP

主カテゴリが math.OC / econ.GN など上記の外にあるものは
対象外とする。ただし cs.LG / stat.ML / econ.EM / q-fin.*
のいずれかにクロスリストされ、かつ4テーマに直接該当する
ものは対象に含める。この例外を適用した場合は明記する。

テーマ(括弧内は優先順位。1が最優先):
・ML/強化学習のトレーディング応用(1)
  最適執行、マーケットメイキング、ポートフォリオ配分、

  マクロファクター投資、レジーム識別、景気循環と資産配分

インデックス。韓国・台湾を対象とした実証は除外する。
理論・手法論で特定市場に依存しない論文は対象に含める。

検索語彙の例(これに限定せず、毎回変えること):
・ML/RL: deep reinforcement learning trading, optimal execution,
  market making, portfolio allocation deep learning,
  transformer financial time series, LLM agent trading
・経済指標: nowcasting, inflation forecasting machine learning,
  GDP nowcasting, MIDAS, mixed-frequency, alternative data macro
・ボラ: realized volatility forecasting, HAR, implied volatility
  surface, neural GARCH, volatility of volatility, quantile
・マクロ: macro factor investing, regime switching,
  business cycle asset allocation, macro momentum

追加で1回以上検索してから0件と報告すること。

━━━━━━━━━━━━━━━━━━━━━━━

主カテゴリ・投稿日を照合する。照合できない候補は要約せず
落とす。創作は厳禁。
査読版が存在する場合はジャーナル名とDOIも併記する。

抄録の全文を取得できなかった場合は、落とさずに通してよいが、
以下を必ず守る:
・Summary と Implication に「抄録冒頭のみに基づく」と明記する
・確認できていない項目(検証データ・市場・ベースライン比較等)は
  推測で埋めず「未確認」と書く
・Notion の Data 欄にも「要確認項目」と記載する

検証不能で落とした候補は、件数とIDを出力末尾に記載する。

━━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━━
新規性・アイデアを優先する。実装容易性や再現性は選定条件に
しない(ただし出力には記載する)。

ここでの新規性とは「問題設定・定式化・データの新しさ」を指す。
モデルアーキテクチャを差し替えただけのものは新規性に含めない。
判断が境界線上にある場合は、その旨を出力に明記する。

品質ガード。以下に該当するものは Low と判定し、
チャット出力にもNotion登録にも含めない:
・既存モデルを別データに当てただけで、ベースライン比較や
  アブレーションがないもの
・バックテストのみで、取引コスト・スリッページ・ルックアヘッド
  バイアスの扱いが記述されていないもの
・「LSTMで株価予測」型の定型論文
・コンペ/共有タスクのシステム報告論文

本数の上限は設けない。上記を通過したものは全件出す。

━━━━━━━━━━━━━━━━━━━━━━━
【出力1: チャット】
━━━━━━━━━━━━━━━━━━━━━━━

・対象期間(拡張した場合はその範囲も)

・実施した検索回数
・本探索が非網羅的である旨

・3行要約

・基準期間外から拾ったものは、投稿日を明示する
・抄録全文が取得できなかったものは、その旨を明示する

末尾に、除外内訳(重複/カテゴリ外/市場フィルタ/テーマ外/
品質ガード/検証不能)を件数で記載する。

## 未解決・要観察

### 1. 新スコープでの負例がゼロ
現時点で新スコープの登録（7件）はすべて「興味あり」または「保留」。避けるべき Field / Method の傾向がまだ学習できず、判定は実質ゼロベースで動いている。**「興味なし」が数件つくまでは学習ループは機能しない。**

### 2. arXiv の列挙不能は解消していない
母集団が見えないため、品質ガードが「厳しすぎて落としすぎている」のか「そもそも該当が少ない」のかを区別できない。定点観測（月初に `/list/q-fin/current` の先頭50件で通過率を測る）案は未着手。

### 3. 抄録全文が取れない原因が未特定
v2.5 で扱いは定義したが、なぜ取れないのかは未調査。arXiv 側の制約なのか探索経路の問題なのかで対処が変わる。

### 4. Cowork のスケジュール実行とエフォート設定
チャット側のエフォート設定がバックグラウンド実行に引き継がれるかは未確認。実際に1回走らせて、出力の検索回数を見るのが確実。

## 破棄された検討事項

### 関連度スコアリング補正（v1.0 時点、v2.0 で破棄）
旧スコープの興味フラグ11件から「判別軸は手法ではなく主題」等の傾向を観測していた。v2.0 でテーマ自体を入れ替えたため無効。

### arXiv API 経由での日付別列挙（v2.3 で破棄）
`export.arxiv.org/api/query` は `submittedDate` の範囲クエリに対応しているが、自動アクセスが robots.txt で拒否される。

### 学習対象の日付カットオフ（v2.4 まで採用、v2.5 で破棄）
「Added が特定日より前を除外」という方式。2026-07-25 に新旧スコープが混在していたため、日付では分離できないことが判明。Paper ID の明示列挙に置き換えた。

## 運用メモ

- 実行は Routine による**完全自動**。水曜 06:50 JST と 土曜 06:50 JST の週2回。
  手動の指示出しは不要。停止・時刻変更の手順は `README.md` を参照
- プロンプトを変更したら、このファイルのバージョンを上げて変更履歴に追記し、main に反映する。
  Routine 側の編集は不要
- Notion DB の `Interest` を「興味あり／興味なし」で埋めることが、学習ループの唯一の入力
